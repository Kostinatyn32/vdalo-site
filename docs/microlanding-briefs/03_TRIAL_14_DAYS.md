# ML-03 | Trial VDALO

## Status

`EXPERIMENT`

14 days is a proposed test, not current approved commercial truth.

## 1. Audience

- actively evaluating new PMS;
- recently dissatisfied with current system;
- opening / launching a property;
- buyer already asking for demo, access or price;
- high-intent lead after audit.

## 2. Primary offer

### Hero

**Спробуйте VDALO у роботі вашого готелю.**

Пройдіть персональний старт і перевірте систему на реальних задачах вашої команди.

**Experiment:** `14 днів без оплати`

**CTA:** `Запросити тестовий доступ`

Use "request access" if self-service provisioning is not operational.

## 3. Core promise

Not "see all features".

Instead:

**Перевірте VDALO на процесах, які важливі саме вашому готелю.**

## 4. Page structure

1. Hero.
2. What can be tested.
3. How start works.
4. Recommended first use cases.
5. Human support / onboarding.
6. Migration question.
7. FAQ.
8. Request access form.
9. Final CTA.

## 5. Capability presentation

Describe only verified scope with qualifiers.

Possible groups:

- reservations / calendar / guest records;
- Channel Manager;
- Booking Engine;
- self check-in / document workflows;
- trigger messaging / AI FAQ;
- RMS / dynamic pricing;
- housekeeping / consumables;
- PRRO / tourist tax / foreign guest workflows;
- smart-energy scope.

Do not imply every module is production-ready for every customer.

## 6. Activation definition

Must be configured before launch.

Recommended model:

`request -> qualification -> tenant setup -> onboarding -> first meaningful action -> usage review`

Choose one primary activation event.

Examples to evaluate internally:

- first reservation created;
- property setup completed;
- team member invited;
- first supported workflow completed.

Do not call "login" activation by default.

## 7. Trial sequence

Proposed experiment:

- D0: onboarding.
- D3: check activation.
- D7: usage review.
- D12: commercial conversation.
- D14: trial end / next step.

Dates are experiment design, not committed support terms.
