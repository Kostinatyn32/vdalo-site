# ML-05 | Розбір одного процесу

## Status

`EXPERIMENT`

## 1. Audience

- cold lead;
- hotelier who does not want a "big audit";
- person who can name one pain but is not ready to evaluate software;
- owner / GM with low time availability.

## 2. Primary offer

### Hero

**Покажіть один процес, який забирає час вашої команди.**

Розберемо його безкоштовно та покажемо, що можна спростити, автоматизувати або залишити під контролем людини.

**CTA:** `Розібрати один процес`

## 3. Process selector

Recommended options:

- запити гостей;
- бронювання;
- заселення;
- housekeeping;
- передача інформації між людьми та системами;
- щоденна / регулярна звітність.

Allow:

`Інший процес`

## 4. Page structure

1. Hero.
2. Choose one process.
3. Example of how analysis works.
4. What participant receives.
5. What happens next.
6. Short form.

## 5. Safe deliverable

After the session:

- clear current workflow;
- repeated manual steps;
- key bottleneck / uncertainty;
- automation candidate;
- what must be verified;
- next-step recommendation.

## 6. Example visualization

`Запит гостя -> хто бачить -> хто вирішує -> хто виконує -> як підтверджується -> де губиться статус`

Label as illustrative scenario, not customer case.

## 7. Form

Required:

- name;
- property;
- contact;
- selected_process.

Optional:

- current_tool;
- room_count.

## 8. Routing

If strong pain:

`One Process -> Full Audit / Pilot`

If actively evaluating PMS:

`One Process -> Trial`

If current PMS is central issue:

`One Process -> PMS Health Check`

If no priority:

`Nurture`

## 9. A/B tests

- `Розібрати один процес` vs `Знайти одну точку автоматизації`.
- selector in hero vs after CTA.
- 10-minute framing vs no time promise. Do not publish time until operationally approved.

## 10. Do not publish

- guaranteed saving;
- "we will automate it";
- fixed implementation time;
- fake ROI calculator without real inputs.
