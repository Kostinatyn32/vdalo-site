# ML-04 | Перехід з іншої PMS на VDALO

## Status

`EXPERIMENT`

Migration scope and "first month free" must be approved before publication.

## 1. Audience

- hotel already paying for another PMS;
- buyer considering replacement;
- pain around migration, duplicate payment, onboarding or fragmented workflows;
- lead who says "у нас уже є система".

## 2. Core insight

The offer should reduce switching anxiety, not attack the competitor.

## 3. Primary offer

### Recommended hero

**Думаєте про зміну PMS? Спочатку перевіримо, чи є в цьому сенс.**

Розберемо вашу поточну систему, критичні процеси та вимоги до переходу.

If approved:

**При переході на VDALO перший місяць без абонплати.**

**CTA:** `Перевірити перехід на VDALO`

## 4. Alternative hook

**Перейдіть на VDALO без подвійної абонплати.**

Use only if the exact commercial rule really prevents duplicate subscription cost.

## 5. Page structure

1. Hero.
2. Switching anxieties.
3. What we assess before migration.
4. What data / workflows may need migration.
5. Transition plan.
6. Free-month logic if approved.
7. What happens if migration is not justified.
8. FAQ.
9. Qualification form.

## 6. Migration assessment

Review:

- current PMS;
- property structure;
- future reservations;
- guest records;
- room inventory;
- rates;
- channels;
- payments;
- historical data needs;
- fiscal/local workflows;
- staff roles;
- integrations;
- cutover risk.

The list is assessment scope, not a promise that every item is automatically migrated.

## 7. Trust message

**Не будемо радити перехід лише заради переходу.**

If current PMS is sufficient for the client's critical workflow, route to:

- Health Check conclusion;
- integration / automation gap;
- nurture.

## 8. Form

Required:

- name;
- property;
- contact;
- current_PMS.

Recommended:

- room_count;
- main_reason_for_change;
- contract_end_date;
- critical_integrations.

## 9. Post-submit

`form -> migration qualification -> current stack review -> decision: stay / test / switch -> migration plan -> commercial`

## 10. FAQ

### Що можна перенести?

Depends on the source PMS, access, data format and agreed scope.

### Чи буде downtime?

Do not promise zero downtime without a tested migration plan.

### Що означає перший місяць без абонплати?

`TO APPROVE`: define whether it covers subscription only, when it starts and what exclusions apply.

### Чи підтримуєте нашу PMS?

Do not use "support" ambiguously. For source migration, verify the exact export/import path.

## 11. Do not publish

- automatic migration from any PMS;
- zero downtime;
- universal data transfer;
- first month free before commercial approval;
- direct competitor claims without current evidence.
