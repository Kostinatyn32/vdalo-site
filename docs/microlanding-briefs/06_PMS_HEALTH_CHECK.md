# ML-06 | PMS Health Check

## Status

`EXPERIMENT`

## 1. Audience

- hotel already using PMS;
- lead objecting "у нас усе є";
- owner unsure whether current system is enough;
- renewal / contract review;
- hotel considering migration but without clear reason.

## 2. Primary offer

### Hero

**Чи ваша PMS справді закриває щоденну роботу готелю?**

Перевіримо, що вже працює добре, що команда досі робить вручну та чи є сенс щось змінювати.

**CTA:** `Перевірити мою PMS`

## 3. Key trust statement

**Результатом перевірки може бути висновок, що змінювати PMS зараз не потрібно.**

This is a strong anti-sales trust mechanic.

## 4. Health Check dimensions

1. Reservations and inventory.
2. Distribution / channel workflow.
3. Guest communication.
4. Check-in / documents / payments.
5. Housekeeping and internal coordination.
6. Reporting.
7. Integrations.
8. Manual work around the PMS.
9. Support / onboarding / migration concerns.
10. Commercial / TCO questions where data exists.

## 5. Page structure

1. Hero.
2. "Already have PMS?" objection.
3. Check dimensions.
4. Three possible outcomes.
5. How assessment works.
6. FAQ.
7. Form.

## 6. Three outcomes

### A. Stay

Current system is adequate for the priority workflow.

### B. Improve around current PMS

There is a manual gap that may be solved without replacing the whole system.

### C. Evaluate switch

There is a justified reason to test VDALO or another architecture.

Do not force every result into C.

## 7. Form

Required:

- name;
- property;
- contact;
- current_PMS.

Recommended:

- room_count;
- biggest_limitation;
- renewal_timing.

## 8. Post-submit

`Health Check -> Stay / Automation Gap / Switch`

Routes:

- Stay -> nurture.
- Gap -> Audit / One Process / Pilot.
- Switch -> Switch landing / Trial.

## 9. Do not publish

- competitor feature claims without dated verification;
- "your PMS is outdated";
- fake score;
- universal compatibility;
- guaranteed savings.
