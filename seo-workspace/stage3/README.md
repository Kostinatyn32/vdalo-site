# VDALO SEO, етап №3: тексти й перелінковка, DELTA-ONLY

**13 жовтня 2026** · 38 URL із переліку власника · 31 унікальний текст-кандидат · 7 свідомих рішень без додаткового SEO-підвалу.

> Це **контентний пакет для застосування в актуальному репозиторії**, а не підтверджене впровадження на сайті. Репозиторій Codex не був доступний у цій сесії, а HTTP-запити до VDALO не вдалося виконати. Назви та наміри сторінок узято з раніше наданого SEO Workspace, а не з фактично прочитаного production HTML.

## Чим пакет відрізняється від етапів 1 і 2

- Не містить нового Master Plan, метаданих, канонікалів, схеми JSON-LD чи нового SEO-аудиту.
- Не перезаписує `00_EXECUTIVE_SEO_STRATEGY.md`, `01_URL_INVENTORY.csv`, `03_INTERNAL_LINKING_MATRIX.csv`, `08_PAGE_EXECUTION_QUEUE.md` та звіти минулих сесій.
- Містить **готові написані тексти** з тематичними H2/H3 і вбудованими Markdown-посиланнями для переведення в наявні HTML/React-компоненти.
- Внутрішні посилання у текстах обрано з **вже наявної матриці**. Наявність URL підтверджена користувачем як основного URL, але не HTTP 200/self-canonical у цій сесії. Codex має перевірити route перед вставлянням.
- Для кейсів не створено жодного твердження про клієнта, досягнутий результат, розмір вибірки чи наявність конкретної функції продукту. Матеріал може бути опублікований лише після звірення з фактичним кейсом, аби загальний коментар не видавали за доказ.

## Як використати

1. Розпакувати `seo-workspace/stage3/` у **чинний** репозиторій VDALO. Не копіювати стару версію всього SEO Workspace поверх фактичних документів Codex.
2. Передати Codex **`CODEX_EXECUTE_STAGE3_DELTA_ONLY.md`**.
3. Codex читає **чинні** статуси й код, перевіряє відсутність або дублювання фрагменту, потім послідовно застосовує тільки потрібні блоки.
4. **Не публікувати** draft там, де він повторює сторінку, містить непідтверджену характеристику або не відповідає наявній версії продукту.
5. Codex записує фактичні зміни, проходження тестів та стан `DONE`, `ALREADY_DONE`, `SKIPPED`, `BLOCKED` у **наявні** регістри.

## Структура

- `content/*.md` — 31 унікальний блок, готовий для контентного diff з актуальною сторінкою.
- `CONTENT_MANIFEST.json` — 38 URL із рішенням про блок, тематикою, шляхом файлу та відомими посиланнями.
- `CONTENT_REGISTER.csv` — початковий реєстр **пропозицій**, не журнал реальної імплементації.
- `CODEX_EXECUTE_STAGE3_DELTA_ONLY.md` — покрокова інструкція для реалізації в репозиторії без повторного аудиту.
- `validate_drafts.py` — локальна перевірка текстів, посилань і повторів до інтеграції.
- `reports/DRAFT_QA_2026-10-13.md` — результати локальної контентної перевірки; це **не** браузерні чи production QA.

## Статусні обмеження

`DRAFT_READY_FOR_CODEX_REVIEW` ≠ `DONE`. `NO_BLOCK_PLANNED` ≠ підтверджений `SKIPPED`. Усі 38 рядків перед перевіркою коду залишаються `PENDING_UNVERIFIED`.

## Стратегічні рішення з базового плану

- Сторінки продукту: процеси та перевірка можливостей, без повторення маркетингового опису.
- Блог: прикладні методи, контрольні ситуації, мікрочеклісти, без дублювання основної статті.
- Кейси: методика й межі тверджень, жодних вигаданих результатів. У разі слабкого кейсу `BLOCKED` до отримання доказів.
- Інструменти: тлумачення результату і межі фінансових моделей, не фіктивні «точні прогнози».
- Службові, авторські, юридичні: не додавати «SEO-текст для SEO».
- Стаття про туристичний збір: без невалідованих ставок або актуальних нормативних тверджень; юридичні цифри потребують окремої фахової перевірки.
